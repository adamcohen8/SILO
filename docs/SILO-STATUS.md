## Implemented capability and evidence

- **Documents:** bounded text/PDF/DOCX/CSV/XLSX/PPTX reads, literal search,
  exact source locators, table statistics, and host-reviewed text/office proposals.
  Optional image OCR needs its own signed runtime; scanned-PDF conversion is absent.
- **Continuity:** encrypted saved projects, task intent/results, code snapshots,
  source/grant invalidation, retention, backups and password-protected recovery.
  Saved records never restore process handles or approval authority.
- **Long work:** interactive work has no lifetime generation/call/run quota.
  Context rollover, per-message bounds, idle/repetition handling and per-process
  resource controls remain. Benchmarks may explicitly use caps.
- **Interfaces:** shared session/host authority with full-window terminal and
  desktop project/source/draft controls. The Mac terminal preview uses fictional
  replies and grants; it is not an actual model or containment test.
- **Models:** eleven pinned text-input profiles, offline import, hardware
  estimates, switching/install/removal. Fresh capable source preparation chooses
  Lightning, with smaller GPU and CPU preparation tiers; saved choices prevail.
  `/model recommend` explains compatible policy-permitted choices without changing selection.
- **Editing:** disposable supported-text repository import, hash-checked edits,
  patch export, Python AST/lexical navigation. Latest native data fixtures cover
  storage, incremental pages, grant revocation and recovery with execution disabled.
- **Execution/publication candidates:** single-process Python execution, separate
  offline build/test runner, pinned NumPy preparation, JS/TS/Rust/C++ adapters,
  reviewed repository application/reconciliation, private-copy local Git commits,
  and read-only contained language services. Each native capability has separate
  gates; no arbitrary shell, task-time package download, Git push or merge tool exists.
